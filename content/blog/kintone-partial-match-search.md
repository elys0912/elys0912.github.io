# はじめに

この記事は 2024-05-11 に [Qiita](https://qiita.com/elys0912/items/06c51fc5dfd82f796442) に書いたものを、本ブログに移して修正した。修正にあたって、公式の資料の確認は AI（Claude Code）と壁打ちしながら進めている。

先に結論を書いておく。

- kintone のクエリで文字列を検索すると、部分一致ではなく単語検索になる
- 英数字は単語単位で検索される。「test1」は 1 語なので、「test」では引っかからない
- 仕様なので API の書き方では避けられない。入れる値の形を決めておくなど、運用で避けることになる

# 起きたこと

kintone のアプリに文字列のフィールドで氏名を持たせ、テスト用に次のようなデータを入れていた。

| レコード | 氏名 |
|---|---|
| 1 | test1 Kintone一郎 |
| 2 | test2 Kintone二郎 |

REST API で `like` を使って部分一致で探すクエリを投げたところ、思った結果にならなかった。

```
氏名 like "test"
```

どちらのレコードにも「test」は含まれているので、2 件返ってくるつもりでいた。実際は 0 件。思わず目を疑ったが、どちらにも含まれる「郎」で探しても 0 件だった。一方で「test1」なら 1 件目、「test2」なら 2 件目がちゃんと返ってくる。

| 検索語 | 結果 |
|---|---|
| test1 | 1 件目がヒット |
| test2 | 2 件目がヒット |
| test | ヒットしない |
| 郎 | ヒットしない |

テストを手当たり次第に叩いていて見つけたもので、仕様を読んでいれば最初から避けられた。備忘として残しておく。

# 原因：クエリの文字列検索は単語検索

API のクエリの書き方の説明（cybozu developer network）には、`like` について「演算子の前に指定したフィールドコードの値が、演算子の後に指定した値を含む」とある。これだけ読むと部分一致に見えるが、補足に次の一文がある。

> クエリで文字列検索する場合は単語検索です。

詳細はヘルプの「キーワード入力時の注意事項」を見るように、とリンクが張られている。ヘルプのほうには、英数字について次の決まりが書かれている。

- 大文字と小文字、全角と半角は区別しない
- 検索は単語単位で行われ、「cy」のような部分一致では検索されない
- 「_」「#」「+」は単語の一部として扱われる。「cybozu_kintone」は分けずにまとめて入力する

日本語（と中国語）は別の決まりで、2 文字以上の単語を検索するには 2 文字以上のキーワードが必要。ヘルプの例では、値が「日本語」なら「日本」「本語」「日本語」では検索できて、「日」「本」「語」ではできない。

これに当てはめると、さっきの結果がそのまま説明できる。

- 「test1」「test2」は英数字の連なりなので、それぞれが 1 語。「test」は語の一部なので引っかからない
- 「郎」は 1 文字のキーワードなので、「一郎」「二郎」のような 2 文字以上の語には当たらない

![検索語ごとのヒットの表。test1 と test2 はそれぞれ 1 件ヒット、test と 郎 はヒットしない。英数字の連なりは 1 語、日本語は 2 文字以上が必要、という理由を添える](/images/kintone-partial-match-search/search-hits.png)

つまり `like` は「含む」と説明されているが、含むかどうかの単位は文字ではなく単語になっている。SQL の `LIKE '%test%'` のつもりで書くと外れるわけだ。

# 対処：仕様なので運用で避ける

API の書き方で回避する方法は見つからなかった。英字の部分一致が使えないのは結構痛くて、kintone にテキストを持たせるなら、入れる値の形を先に固めておかないと「データはあるのに取れない」事故が続く。

今回取ったのは次の対処。

- バリデーションで、kintone に保管する値の形を厳密に決め、検索の使い方に合わせる
- kintone を使うと決まった時点で、検索のしかたを運用のルールに盛り込む

英字と数字をくっつけた値を検索したい場面があるなら、そもそもくっつけないで済む形にするのが一番素直。プロジェクトの規約と突き合わせた結果、運用で避けるくらいしか手が浮かばなかった。

ほかに考えられる手もある。いずれも試していないので、使うなら先に動作を確かめてほしい。

| 手 | 中身 | 気になる点 |
|---|---|---|
| 検索用のフィールドを別に持つ | 英字と数字の間に空白を入れるなど、単語に分けた値を別のフィールドに入れておき、そちらを検索する | 元の値と検索用の値を常にそろえる仕組みが必要 |
| 広めに取ってから絞る | 単語で当たる条件や別の条件で多めに取得し、部分一致の判定はアプリ側で行う | 件数が多いと取得の回数と時間が増える |

もっとも、参考にした記事では 1 文字・部分一致の検索ができるプラグインが紹介されている。プラグインを入れられる環境なら、それが一番手っ取り早いかもしれない。

# まとめ

- kintone のクエリの文字列検索は単語検索。`like` でも部分一致にはならない
- 英数字は連なり全体が 1 語。「test1」は「test」では取れない。大文字と小文字、全角と半角は区別しない
- 日本語は 2 文字以上の語に 2 文字以上のキーワードが必要
- API の書き方では避けられないので、値の形と検索のしかたを運用で決めておく

「含む」という説明を SQL の感覚で読むと、まず引っかかる仕様だと思う。kintone を使う案件では、最初にこのヘルプを読んでおくと後で困らないからね。
