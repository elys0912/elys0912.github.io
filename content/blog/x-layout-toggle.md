Twitter（いまの x.com）の画面には、使わないものが多い。たとえば左メニューの Grok やプレミアム、右サイドバーのプレミアムの勧誘やスポーツの速報。どれも毎日目に入るのに、押すことはまずない。

そこで、左メニューの項目と右サイドバーのブロックを 1 つずつ表示・非表示にできる Firefox 拡張「Layout Toggle for Twitter」を作った。Claude Code と一緒に、設計案の画面のイメージを作るところから始めて、実機での確認まで進めている。どの項目を対象にするか、名前やアイコンをどうするかは、こっちで決めた。

この記事で扱うのは次の 4 つ。

- できること（画面つき）
- 項目の見分け方と、隠し方
- 「もっと見る」の項目を左メニューへ移すしくみ
- 作る途中で引っかかったこと

# できること

拡張を入れる前の画面がこれ。画像の中の投稿や右サイドバーの中身は、他の人の投稿やアカウントが写るのでぼかしてある。

![拡張を入れる前の x.com。左メニューに Grok とプレミアム、右サイドバーにプレミアムの勧誘が並んでいる](/images/x-layout-toggle/05.png)

拡張を入れると、初期設定のままでこうなる。

![初期設定の画面。左メニューから Grok とプレミアムが消え、代わりにリストとコミュニティが並んでいる。右サイドバーはプレミアムの勧誘が消えている](/images/x-layout-toggle/06.png)

初期設定で隠すのは次の 7 つ。

- 左メニュー：Grok、プレミアム
- 「もっと見る」の中：ビジネス、広告
- 右サイドバー：プレミアムの勧誘、ライブ放送、スポーツ速報

ホームと「設定とプライバシー」は、隠すと戻る手段が減るので初期設定では表示にしてある。

設定は拡張機能の設定画面（`about:addons` → Layout Toggle for Twitter → 設定）で切り替える。切り替えた時点で保存され、開いている x.com のタブにも読み込み直さずに反映される。

![設定画面。左メニュー・「もっと見る」の中・右サイドバーの欄に、項目ごとのスイッチが並んでいる](/images/x-layout-toggle/10.png)

右サイドバーは「すべて隠す」で丸ごと消せる。

![右サイドバーをすべて隠した画面。右側が空いている](/images/x-layout-toggle/07.png)

このままだと右側が空いたままになる。設定の「右サイドバーをすべて隠したら、タイムラインを広げる」をオンにすると、空いた分までタイムラインが広がる。

![タイムラインを広げた画面。投稿が画面の右側まで広がっている](/images/x-layout-toggle/08.png)

広げると、画像つきの投稿は画像も大きくなる。1 件で画面がほぼ埋まるので、ここは好みが分かれるところだと思う。初期設定ではオフにしてある。

# 見分け方と隠し方

x.com の画面は React で作られていて、クラス名は意味のない文字列になっている。そのため、クラス名では項目を見分けられない。代わりに使ったのは `data-testid` という属性と、リンク先（`href`）だ。

2026-10-29 に、x.com のホーム（日本語の表示）の DOM を読んで見分け方を決めた。ほとんどの左メニューの項目には、`AppTabBar_Home_Link` のような `data-testid` が付いている。付いていない Grok と履歴は `href` が `/i/grok`、`/i/history` なので、それで見分ける。

右サイドバーのブロックには、ブロックそのものに `data-testid` が付いていない。ただ、中身には手がかりがある。

| ブロック | 手がかり |
|---|---|
| 検索ボックス | `SearchBox_Search_Input` を含む |
| プレミアムの勧誘 | `/i/premium_sign_up` へのリンクを含む |
| ニュース | `news_sidebar` を含む |
| スポーツ速報 | `mlb_scores_sidebar` のように `_scores_sidebar` で終わる testid を含む |
| トレンド | `trend` を含む |
| おすすめユーザー | `UserCell` を含む |
| フッター | 利用規約（`/tos`）へのリンクを含む |
| ライブ放送 | `pill-contents-container` を含む |

ライブ放送の手がかりは、ほかのブロックにも出てきそうな汎用の名前だった。そのため、判定の順番を最後にして、ほかのどれにも当たらなかったときだけライブ放送とみなしている。

画面の文字（「おすすめユーザー」など）は使っていない。表示の言語を変えると文字も変わるからだ。属性とリンク先だけで見分けているので、英語の画面でも同じように動くはず。

隠し方は単純で、見分けた要素に `data-xlt="side.news"` のような印の属性を付け、ページに差し込んだ `<style>` の CSS で隠す。要素そのものは消さない。こうしておくと、x.com の作りが変わって見分けに失敗したときは、印が付かずに全部表示のままになる。間違って大事なものが消えるより、消えないほうがましだと考えた。

x.com はページを読み込み直さずに画面を描き直すので、`MutationObserver` で DOM の変化を見て、印を付け直している。描き直しは 1 フレームの間に何度も起きるので、判定は `requestAnimationFrame` で 1 フレームに 1 回にまとめた。

# 「もっと見る」の項目を左メニューへ移す

項目を隠していくと、左メニューは短くなる。せっかく空いたので、隠した数だけ「もっと見る」の中の項目を上から順に左メニューへ移すようにした。

![左メニューを 5 つ隠した画面。リスト・コミュニティ・クリエイタースタジオ・コミュニティノート・スペースを作成が左メニューに並んでいる](/images/x-layout-toggle/09.png)

やっていることは次のとおり。

- 「もっと見る」のメニューは開いている間だけ DOM にある。開かれたときに、中の項目の名前・リンク先・アイコンの形（SVG の `path`）を読んで保存しておく
- 左メニューの既存の項目（「話題を検索」）を複製して、アイコンと名前とリンク先だけを差し替える。x.com のクラスをそのまま持つので、見た目は元の項目とそろう
- メニューの中の元の項目は隠す

複製したリンクは、そのままだと普通のリンクとして動き、押すたびにページ全体を読み込み直してしまう。そこで、押されたら `history.pushState` で URL を変え、`popstate` のイベントを送るようにした。x.com はこのイベントで URL を読み直すので、本物の項目と同じように画面だけが切り替わる。「戻る」も使える。これは実機で試してから決めている。

一方で、Ctrl を押しながらのクリックや中ボタンのクリックは、ブラウザに任せている。新しいタブで開く操作を邪魔しないためだ。

名前の長い項目（クリエイタースタジオ、コミュニティノート）は、左メニューの幅に収まらずに「…」で切れる。幅は x.com の CSS が決めているので、ここは仕方がない。

# 作る途中で引っかかったこと

## 設定画面だけ「許可されていない」と言う

最初の版では、設定画面で `browser.permissions.contains` を使って x.com へのアクセスが許可されているかを確かめ、許可が無ければ案内を出すようにしていた。ところが、x.com では拡張が動いているのに、設定画面には「許可されていない」と出た。案内の「許可」のボタンを押しても、ダイアログは出ず、表示も消えない。

調べると、Manifest V3 の Firefox では、サイトへのアクセス許可は使う人があとから外せる扱いになっている。許可が無いサイトでは content script が動かない。さらに、about:debugging で一時的に読み込んだ拡張には、許可を求める確認が出ない。

今回は途中で拡張の ID を変えたところで、x.com でも拡張が動かなくなった。それで事情が見えた。それまで動いていたのは、前に同じ ID の版をファイルから入れたときの許可が残っていたからのようだ。`permissions.contains` が false を返した理由までは突き止めていない。

結局、`permissions.contains` で確かめるのはやめた。代わりに、content script が x.com で動いた時刻を保存して、設定画面はその記録があるかどうかで判断している。「動いたかどうか」を直接見るほうが確実だ。

## hidden 属性が効かない

上の案内には、まだ続きがあった。動いた記録があるのに、案内が消えない。

原因は CSS で、案内の枠に `display: grid` を指定していた。HTML の `hidden` 属性は、ブラウザが既定で持つ `display: none` の指定で隠しているだけなので、ページの CSS で `display` を指定するとそちらが優先される。設定画面の CSS に次の 1 行を足して直した。

```css
[hidden] {
  display: none !important;
}
```

知っていれば当たり前の話だが、気づくまでに少しかかった。

## タイムラインが広がらない

右サイドバーを消してタイムラインを広げる機能は、最初、タブの帯だけが広がり、投稿は真ん中に寄ったままだった。タイムラインの枠（`primaryColumn`）の幅の上限は外していた。ただ、その 2 段下にある投稿を並べる入れ物にも、別に 600px の上限が付いていた。

この上限も外して、投稿まで広がるようにした。返信やいいねのボタンが並ぶ行にも 600px の上限があるが、こちらは残している。ボタンが画面の端から端まで散らばると、かえって押しにくい。

# 作りと配布

TypeScript で書いて、esbuild で束ねている。圧縮はしていない。テストは Node.js の `node:test` で、使う人の操作の場面（左メニューを 2 つ隠すと「もっと見る」の上から 2 つが移る、など）と境目の値に絞って 33 件。DOM に触れる部分は実機の x.com で確かめた。

保存するのは、表示・非表示の設定、x.com で見つけた項目の名前とリンク先、x.com で最後に動いた時刻だけで、どこにも送らない。

名前はいまの x.com ではなく Twitter 時代の呼び方にした。アイコンはほかの自作の拡張と同じ時計と狐の形で、色を Twitter 時代の青にしてある。X Corp. とは関係のない個人の拡張だ。
