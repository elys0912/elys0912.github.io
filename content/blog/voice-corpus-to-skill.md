# はじめに

このブログの記事は、AI（Claude Code）と壁打ちしながら下書きを作り、自分で直している。困っていたのは、下書きがどうしても AI の文になること。間違ってはいないけど、自分の文には見えない。

どこが違うのかを言葉で説明しようとして、できなかったのがきっかけ。「自分ならこう書かない」は毎回わかるのに、じゃあどう書くのかを自分でわかっていない。

そこで、Mastodon に 8 年間書いてきた自分の投稿から口調を数えて資料にし、それを Claude Code の Skill にした。記事を書いた後に Skill を通すと、資料に照らして直す案が出てくる。

先に書いておくと、投稿の本文はこの記事に載せない。数えた結果と、やり方だけを書く。

# 集める

対象は自分の投稿だけ。ブーストと DM は外し、返信は含めた。アカウントを作った 2018 年 7 月から 2026 年 10 月まで、31 万件ちょっとある。

最初の 11 万件ほどは、ブラウザで API を読むスクリプトを動かして取った。レート制限に当たるたびに止まるので、解けるのを待って古いほうへ続ける。残りは週 1 回の自動収集に回してあって、ヘッドレスの Claude Code が手順書を読んで、新しい投稿と、まだ取っていない古い投稿を足していく。今は最初の投稿まで取り終わっている。

取るときに伏せ字をかけている。

- 他人の ID は `@user1`、`@user2` に置き換える。対応表は残さない
- 添付は種類と自分が付けた代替テキストだけ残して、URL は保存しない。引用先の他人の本文とリンクカードの中身は保存せず、有無だけ残す
- 置き換えの漏れは、本文に残った `@` の形だけを表示する検査で数える。本文そのものは表示しない

生データは手元のリポジトリだけに置き、外には出さない。集計の出力にも本文は載せない。語尾や記号の形と、その数だけにしてある。

# 数える

集計は Python で、形態素解析には janome を使った。全部を流すと 1 回 20 分くらいかかる。

数えたのは主にこれ。

| 観点 | 中身 |
|---|---|
| 語尾 | 末尾の 1〜6 文字、末尾の形態素、行末ごとの語尾 |
| 語彙 | 一人称・二人称、終助詞、口癖の出現率 |
| 表記 | 句読点、笑いの表し方、全角と半角、絵文字・顔文字 |
| 長さ | 投稿の文字数、行数、行の長さ |
| 時期 | 1 年ごとの変化 |

基準は直近 1 年にした。8 年分を全部まとめると、投稿が多かった時期に引っ張られて、今の口調から離れる。年の窓は最新の投稿から 12 か月ずつ遡って切るので、投稿が増えると窓がずれる。前回と比べるときは起点の日時を固定して流す。

貼り付けや定型文も混ざっている。タグ付き、普段使わないクライアントからの投稿、同じ本文が 3 回以上あるもの、などに印を付けて、印のないものを「本人の文」の基準にした。

# 分かったこと

数えてみると、自分では気づいていない癖がかなりあった。

- 1 投稿は 15 字前後で、9 割が 1 行。句点は実質打たない
- 語尾は「〜ない」「〜た」「〜か」「〜な」「〜んだよな」が多い
- 笑いは「草」が主で、（笑）はほとんど使わない
- 冗談の後ろに「（？）」を付けて自分で打ち消す。「〜とされる」みたいな硬い言い方をとぼけて使う
- 8 年で文は長くなり、丁寧語は減った。「（？）」や「〜とされる」は 2022 年の秋から増えている

「〜とされる」は、言われてみればよく使ってるなぁ。

# 記事に移す

困ったのはここから。資料は短文投稿のもので、記事は長い文章。そのまま移すとおかしくなる。

## 形は持ち込まない

句点を打たない、1 行で切る、改行で文を区切る、というのは投稿の形から来ている。記事でやると読めない。記事には語尾・語彙・言い回しと「やらないこと」だけを移し、句点を打って段落を作ることにした。

## 資料を読ませると行き過ぎる

資料なしで書かせた文章と、資料を読ませて書かせた文章を比べた。資料ありのほうは「〜よな／〜んだよな」が 100 文に 8 回出た。直近 1 年の投稿の約 4 倍になる。「〜とされる」は 1 本に 2 回出て、こっちは約 6 倍。特徴を教えると、AI はそれを全部の文に使おうとするんだよな。

なので、上限を決めた。

| 語 | 上限 |
|---|---|
| 〜よな／〜んだよな | 100 文に 2〜3 |
| 〜とされる | 1 本に 1 回 |
| すぎ・だろ・マジ・やば・（？）・草 | 1 本に 0〜1 回 |

崩した言い方は、感想・持論・締めにだけ置く。手順や表の説明は崩さない。

## 報告調は資料だけでは直らない

記事の文末を数えると、「〜た」が 2 割を超えていた。投稿では 7% くらいしかない。「〜した。〜した。〜した。」と経緯を並べる書き方は、資料を読ませても直らなかった。

これは書き換えの例を資料に足して対処した。経緯の文の何割かを「〜してある」「〜してる」のような状態の言い方にして、段落の締めに「か」「なぁ」「かな」を置く。

## 言葉を置き換える

投稿には、記事に書くと品のない語や、内輪の略語も混ざっている。これは置き換えの表を作った。「クソ〜」は「ひどい〜」、「ガチ」は「本気で」、のような具合。目標は「フランクなブログとして違和感がない」ことにした。

# Skill にする

資料は 600 行近くあって、毎回全部を読ませるのは重い。Skill には、要約と「記事に移すときの目安」と「やらないこと」を中心に読ませて、使い方を決めた。

1. 記事を読み、資料に照らして違うところを拾う
2. 直す案を表で出す（元の文、直した文、根拠の章）。本文は直接書き換えない
3. 承認したところだけ反映する
4. 反映した後に、上の上限を数えて確かめる

Skill は Skill の中で完結させた。元の資料の置き場を参照させると、置き場が変わったときに動かなくなる。資料は Skill の中に写しを置いて、元を更新したら写し直す。

# 限界

数えて分かるのは、短文投稿での口調だけ。

- 文と文のつなぎ方や、段落の運び方の根拠が無い。空行のある投稿は 1 年で 48 件しかない
- 説明文の口調の根拠がほぼ無い。100 字を超える投稿は少なく、あっても貼り付けが多い
- 読み手が違う。投稿は独り言に近く、知らない人に説明する場面のデータが無い
- 直近 1 年はサッカーの実況に寄っていて、話題の差と口調の差を分けられていない

なので、技術の説明の部分は、資料ではなく自分で決めた方針で書いている。資料が効くのは、感想と締めの何文かくらい。それでも、AI の下書きを自分の文に寄せる手がかりとしては十分使える。

# まとめ

- 口調は数えられる。自分の癖は自分では分からない
- 生データは外に出さず、出力には形と数だけを載せる
- 特徴を教えると AI は全部の文に使う。上限を決める
- 短文の形と記事の形は別物。移すのは語尾と語彙と「やらないこと」だけ

この記事も Skill を通してある。どこまで自分の文に見えるかは、読んだ人の判断に任せたい。
