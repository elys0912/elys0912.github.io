# はじめに

遊んでいるゲーム（ステラソラ）のキャラ育成で、「目標のレベルとスキルまで、素材があと何個足りなくて、何周して、何日かかるのか」を毎回頭の中で概算していた。公式のデータ公開も API も無いので、きちんとやるなら土台から作るしかない。

そこで、育成データを自家製の DB（JSON）として整備し、その上で逆算する CLI ツールを作った。実装は AI（Claude Code）と進め、データの正しさの判断はこっちで持つ。この記事は、データが無いところからどう埋めたかと、埋まらないものの扱いを書く。

# データの出どころは 3 つ

1. **攻略 wiki の転記**：共通の表（素材・コスト）はスクレイプ補助のスクリプトで候補を作り、目で確かめてから DB に写す。wiki へのアクセスは 1 秒以上の間隔を空け、必要なページだけ、HTML はキャッシュして二度取りしない。画像は保存も転載もしない
2. **ゲーム内の実測**：wiki に無い・wiki が怪しいものは、ゲーム内で目で見て手入力する。ステージ 54 件の報酬はこれで埋めた
3. **自分の周回記録**：数の表示が無い確率ドロップは、周回の結果を 1 回ずつ記録して期待値を出す

ポイントは、スクレイプの結果を直接 DB に書かないこと。候補と差分を出すところまでが機械の仕事で、DB に写すのは人間の確認を通ったものだけにしてある。wiki は人の手で書かれたものなので、転記ミスも「不明」のままの欄も普通にある。機械的に信じると、逆算の結果ごと静かに狂う。

# 未確認の仕様は null＋課題台帳で運ぶ

この設計で一番気に入っているのがここ。確認できていないゲーム仕様は、それらしい値で埋めず null のまま運び、課題台帳（issues.json）に「何が未確認か・どう確かめるか」を 1 件ずつ積む。

たとえばランクごとのレベル上限は、確認が済むまで仮の式で警告だけ出す。箱の中身は手持ちに無くて開けられないので、台帳に積んだまま null で待つ。逆算の結果には「この値は未確認」という留保が残るので、結果だけ見て確定と思い込む事故がない。

推測で埋めたくなる誘惑は強い。埋めれば計算は通るし、見た目は完成に近づく。ただ、推測値は一度入ると出どころが消えて、後から「これは測った値か、置いた値か」が分からなくなる。null は不便だが、不便さがそのまま「まだ確認していない」の印になっている。

# 期待値は自分の記録から出す

確率ドロップの個数は wiki にも無いことが多い。これは周回のたびに結果を記録するコマンドを用意して、記録が溜まると期待値が出る形にした。

```
python scripts/add_drop.py basic_6 --option guide --runs 3 --item guide_t2=15 --item guide_t1=75
```

報酬 2 倍の日の周回は、印を付けて別に数える。混ぜると標準の期待値が上に歪むので、集計の分母を分けておく。この辺は仕事のデータ集計と同じで、「何を 1 と数えたか」を記録の時点で区別しておかないと、後から分けられない。

# 逆算そのもの

目標（誰をどこまで育てるか）と在庫を JSON で渡すと、不足素材 → 周回数 → やる気（スタミナ）→ 日数、と順に割り付けて plan.md を書き出す。チケット制のコンテンツは別枠で数えるなど、ゲームの仕組みに合わせた細かい分岐はあるが、計算自体は地味な積み上げ。難しいのは計算より入力データの正しさのほうだった。

# まとめ

- 公式データが無くても、wiki 転記＋実測＋自分の記録の 3 層で DB は作れる
- 機械は候補を作るまで。DB に写すのは人間の確認を通ったものだけ
- 未確認の値は推測で埋めず、null＋課題台帳で「未確認であること」を保存する
- 期待値は分母の条件（2 倍の日など）を記録の時点で分ける

1 タイトル専用に割り切ったので、作りは小さい。それでも「あと何日」が根拠付きで出るだけで、周回の気の持ちようが違うんだよな。
