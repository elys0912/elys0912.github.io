# はじめに

遊んでいるゲーム（ステラソラ）のメインストーリーを、後から読み返せる形で手元に残したくなった。公式に履歴の機能はあるが、「どの話に誰が出たか」「分岐でどれを選んだか」を横断して見る手段はない。

そこで、ストーリー画面のスクリーンショットから OCR で会話を読み取り、章ごとの記録（Markdown）に起こすツールを作った。記録もスクリーンショットも外部に送らない完全ローカル動作で、ゲームデータの改変・メモリ読み取り・通信傍受はしない。見るのは画面だけ、という線引きにしてある。実装は AI（Claude Code）と進め、設計の判断は自分でした。

# 作りの全体

パイプラインは 3 段になっている。

1. **画面の分類**：テンプレートマッチで「会話」「選択肢」「章の開始・終了」を見分ける。テンプレートは実機の画面から切り出し、台帳（manifest）に版番号を付けて管理する
2. **読み取り**：会話の本文と話者の名札を OCR で読む。イベントは 1 行 1 件の JSONL に追記のみで記録し、書き換えはしない
3. **記録の生成**：JSONL から章ごとの Markdown を作る。選択肢・話者・章遷移が付いた「手帖」になる

OCR エンジンは抽象化して差し替えられるようにし、Windows 標準・RapidOCR・manga-ocr を実画面のサンプルで比較してから決めた。しきい値や読み取り範囲（ROI）も、思い込みで決めずに検証スクリプトで実測してから固定する。この「先に測って確定欄を埋める」進め方は、後で書く誤読対応でも効いた。

# OCR は誤読する。辞書で直す

OCR は名前をよく読み違える。カタカナの「エ」を漢字の「工」、「ル」を「ノレ」、「ハ」を「ノ、」と読む系統の誤りが多い。字形が近いので、エンジンを替えても完全には消えない。

これはエンジン側で粘らず、名寄せ辞書（names.json）で吸収する方針にした。「工ノレ」と読めたら正しい名前に写す、という対応表を運用しながら手で育てる。選択肢や章ラベルの表記ぶれも、同じ形の同定辞書で吸収している。

正しい名前の確認には攻略 wiki のキャラ名一覧と照らした。OCR の出力をそのまま信じず、既知の一覧と突き合わせて初めて確定にする。読めない数件は無理に埋めず、読めないまま残してある。

# 抜けを見える化する

記録もの一般に言えるが、怖いのは「記録したつもりで抜けている」こと。対策として、章ごとの話の一覧（episodes.json）を先に手で書き、記録と突き合わせて未記録の話を一覧に出すようにした。全話そろったかが機械的に分かるので、「たぶん全部読んだ」で終わらせずに済む。

いま、メインストーリーの九章分が記録になっている。分岐の選択肢は毎回 1 番目を選んでいるので、分岐グラフはまだ 1 本道しか見えていない。別の枝を埋めるのはこれからの楽しみとされる。

# 作ってよかったこと

- 「この人いつから出てたっけ」が、話数×登場キャラの一覧で引ける
- 誤読の辞書が育つほど後の章が楽になる。手間が資産になる形は続けやすい
- 追記のみの JSONL ＋ 生成は Markdown、という分け方のおかげで、記録の形式を後から変えてもやり直しが利く

# まとめ

- スクリーンショット → 分類 → OCR → 追記のみの記録 → Markdown 生成、の一方通行
- OCR の誤読はエンジンで粘らず、名寄せ辞書を運用で育てて吸収する
- 話の一覧を先に書き、未記録を機械的にあぶり出す
- 外部に何も送らない・ゲームに何もしない、の線引きは最初に決めて守る

ゲームの攻略情報は wiki に揃っていても、「自分がどう読んだか」は自分で残すしかない。この手帖は読み返すたびにちょっと嬉しい。
